# Content & Copyright Policy

## 1. Purpose

AgoCode is strongly inspired by the pedagogy and topic progression of *Grokking Algorithms* by Aditya Bhargava, published by Manning.

The repository is public, so the project must distinguish between:

- learning from the book's structure and teaching ideas,
- referencing the book,
- creating original educational material,
- reproducing copyrighted expression.

The first three are acceptable project activities. The last requires permission and should be avoided by default.

## 2. What AgoCode may use as inspiration

AgoCode may use high-level pedagogical principles such as:

- example-first explanation,
- visual mental models,
- short exercises placed near concepts,
- gradual movement from intuition to implementation,
- discussion of algorithm trade-offs,
- chapter recaps,
- the book's broad chapter/topic sequence.

AgoCode may also teach the same algorithms, data structures, mathematical ideas, and standard programming techniques. Algorithms and ideas themselves are not copied merely because they are also taught by the book.

## 3. What must be original

The following should be created specifically for AgoCode:

- prose explanations,
- lesson wording,
- illustrations,
- diagrams,
- interactive scenes,
- UI copy,
- exercises where reasonably possible,
- visual assets,
- animations,
- examples beyond unavoidable standard algorithm examples,
- code annotations,
- recap prompts,
- transfer activities.

## 4. Do not copy book assets

Do not commit or ship:

- scanned pages,
- screenshots of pages,
- book illustrations,
- traced/recreated versions that are substantially identical,
- long copied passages,
- copied chapter text,
- copied exercise sets or answer keys,
- publisher branding or layout replicas that create confusion about affiliation.

## 5. Original illustration policy

The design system may be inspired by the book's broad illustrated/editorial character, but illustrations must be independently created.

Acceptable direction:
- black-ink line work,
- limited red accent,
- simple hand-drawn objects,
- annotated diagrams,
- playful but instructional visual metaphors.

Not acceptable:
- redrawing a specific book illustration scene-for-scene,
- copying character poses,
- recreating a page layout so closely that it appears to be the original page.

## 6. Text quotation policy

Avoid quotations in product lessons unless there is a specific reason.

If short quotations are used in documentation for commentary or attribution:
- keep them brief,
- clearly attribute the source,
- do not use them as a substitute for writing original teaching content.

## 7. Chapter structure

AgoCode may map its Book Track to the chapter sequence because the project intentionally follows the book as a curriculum reference.

Use chapter/topic names only to the extent needed for factual reference and navigation. The interactive lessons themselves should be independently authored.

## 8. Code

Standard algorithm implementations are often conventional. However:
- prefer AgoCode's own modern Python 3 implementations,
- do not copy surrounding explanatory annotations from the book,
- test behavior independently,
- clearly document any external code that is incorporated under an open-source license.

The source book uses Python 2.7; AgoCode should modernize examples to Python 3 unless a historical note is specifically useful.

## 9. External problems

When linking to LeetCode or another problem platform:
- store the title, source, URL, tags/metadata, and AgoCode-specific instructional notes,
- do not copy the full problem statement into the repository unless the license/terms allow it,
- prefer linking out or writing an original analogous internal exercise.

## 10. Attribution

Documentation should state that the canonical Book Track is pedagogically inspired by:

> Aditya Y. Bhargava, *Grokking Algorithms: An Illustrated Guide for Programmers and Other Curious People*, Manning Publications.

Do not imply endorsement, partnership, or official adaptation status unless permission is obtained.

Suggested wording:

> AgoCode's Book Track is inspired by the chapter progression and visual/example-first teaching philosophy of *Grokking Algorithms*. AgoCode is an independent project and creates its own interactive content, illustrations, exercises, and implementations.

## 11. Repository review checklist

Before merging new educational content, verify:

- [ ] prose is original,
- [ ] illustrations are original,
- [ ] no scanned book material is committed,
- [ ] no long passages are reproduced,
- [ ] external problem text is not copied without permission,
- [ ] source references are factual and appropriately attributed,
- [ ] code licenses are respected,
- [ ] the content does not imply official affiliation with Manning or the author.

## 12. If exact book content is needed

If a future feature requires reproducing substantial book text, illustrations, exercises, or page designs, do not assume that owning a copy of the book grants republication rights.

Pause implementation and obtain appropriate permission/licensing before shipping that material publicly.
